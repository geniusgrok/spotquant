# Spotquant

个人使用的 Binance BTCUSDT 现货交易程序。当前策略为单仓 SMA40。日线影子账面按两根已完成收盘、252 日过滤、新鲜穿越和修复规则产生信号，在真实到达的下一日开盘单次换仓，入场价格用该开盘价；未完成日线的高、低、收盘不参与信号。账户只在会话跟随它。会话看到第一根重新站上均线的收盘就可以先买。趋势仓在会话价格回到均线 0.5% 以内时卖出；该卖单保留 touch 再入许可，影子账面仍持有且出现更新的已完成日线后，后续会话才可买回。普通退出和原生止损消费旧信号，需要新的入场信号。修复仓身份从入场保留到实际持仓，交接前免于均线、过度伸展和 4% 不利收盘退出，保护穿价仍优先。保护目标为成交后已验证观察高点回撤 28%。拥挤度只影响新的买入。只做多或持有 USDT，不借币、不做空、不使用杠杆。默认只读，手动启动有限会话，没有后台守护进程；仅依赖 Python 3.13 标准库。

普通空仓若影子账面已持有、已完成收盘仍高于均线且未过度伸展，而当前会话价格已在均线 0.5% 的卖出区域，先保持空仓；价格离开该区域后才可买入。修复信号和影子账面尚未加入的提前入场沿用原规则。拒绝这种买入可减少立即买卖的费用，也可能延后或错过回升。实际卖出的已完成日线仍被锁住，价格回升不会解除它。

会话先卖后买会多付一次费用，换的是在收盘跌破均线之前离开已经回到均线的趋势。4% 不利收盘退出等到下一会话执行，实际损失可能超过 4%；原生保护距离为 28%，停机期间保留最后确认的保护价。离线收益与复现材料保存在私有研究载体；UM 1 分钟行情只能作为现货价格代理，不能认证现货成交或主网执行。

## 配置与只读运行

在仓库目录内使用 Python 3.13，无需安装第三方包。

```sh
cp config.example.json config.json
python3 -m spotquant status --config config.json
python3 -m spotquant run --config config.json
python3 -m spotquant snapshot --config config.json --out /tmp/spotquant-snapshot.json
```

先填写 `config.json` 的 `account_uid`，使用核验一致的 Binance UID；`state_dir` 使用该账户固定目录。配置不存凭据。

| 字段 | 用法 |
|---|---|
| `environment` | `live`（默认）或 `demo`，账户、凭据和状态分别隔离 |
| `session_seconds` | 会话时长 1～86400 秒，默认 300 |
| `poll_seconds` | 轮询间隔 1～60 秒，默认 5，不超过会话时长 |
| `capital_limit_usdt` | 可选正值十进制字符串，按当前全账户 BTC 名义约束新增买入；不因持仓升值主动减仓，不是亏损上限 |

主网凭据从 `SPOTQUANT_BINANCE_KEY`、`SPOTQUANT_BINANCE_SECRET` 读取，Demo 从 `SPOTQUANT_BINANCE_DEMO_KEY`、`SPOTQUANT_BINANCE_DEMO_SECRET` 读取。两套凭据互不回退。

`status` 观察一次；`run` 在期限内读取行情、账户和订单状态，输出策略与订单预览。`snapshot` 导出新鲜只读账户 JSON，输出文件必须不存在。`run --execute` 被程序阻止，主网下单不可用。

## Demo 会话

```sh
cp config.demo.example.json demo.json
python3 -m spotquant demo-check --config demo.json
python3 -m spotquant demo-check --config demo.json --execute --authorize-uid <DEMO_UID>
```

填写专用 Demo UID、固定状态目录和正值资金上限。执行需显式 `--execute`，且 `--authorize-uid` 与配置一致。冷启动等待新鲜穿越，不强造入场；SELL 优先于新 BUY，不预支预计卖出所得。

订单发送前保存原生身份、成交归属和入场身份，部分成交按实际回读归属；成交均价按成交毛数量累计，持仓数量保留扣费后的余额。同一 BUY 后续较高价成交同步提高持仓及修复高点。已接受止损的价格下限绑定其实际持仓，不能带到后来新买的仓位。未知委托、成交或余额变化阻止新增风险；丢失回包后查询原身份，不重复发送未知订单。保护目标为成交后已验证观察高点回撤 28%，不会放宽同一持仓确认生效的止损。现货更换止损需先撤旧单再挂新单，存在保护空窗。

Demo BUY 前读取当前手续费和交易所最小额，按最新成交价估算扣费及数量取整后的可保护数量。启用第三资产手续费折扣、费率接口不可用，或历史第三资产费用尚未估值时拒绝新增 BUY；程序不更改交易所设置，已有持仓的止损与减仓仍可继续。第三资产成交费会保留原资产数量并标记财务估值未完成；BTC/USDT 余额及订单归属仍须核对。已有持仓的退出与保护决策不等待拥挤度公共输入；这些输入只约束新的 BUY。止损穿价判断使用新取的最新成交价，均价只用于名义金额过滤。明确拒绝的止损会尝试市价减仓；网络超时或交易所内部错误仍按未知订单原身份查询。会话到期即停止新增 BUY；正常到期后如有未决订单，最多在后续 30 秒内尝试一次原身份恢复及保护收尾。无法确认的剩余仓位在本地报告中标为人工接管。

会话内持仓峰值来自实际成交及成交后运行时观察到的已验证报价，不使用成交前的未完成日线高点。轮询观察不等于完整 tick 最高价。会话结束后只保留最后真正确认生效的原生保护；进程停止期间不改单。下次会话根据新的实际报价更新保护目标，只有实际原生回读接受后才视为生效，不能回溯为停机期间持续生效的移动止损。Demo 回读和只读快照不代表主网执行已验证。

固定状态目录的 `latest.json` 保存最新报告。成功观察包含 `risk_state`（余额、已确认止损覆盖、未保护数量、第三资产费用估值及观察时间）、`execution_evidence`（报价、成交/止损回读、费用及滑点）；`status` 和 `run` 也记录 `runtime_identity`。市价单的成交滑点以生成意图时的账户复核报价为参考，包含提交前变价，不能视为纯延迟滑点。可选环境变量 `SPOTQUANT_SOURCE_SHA` 记录操作者提供的部署提交，未设置时为空。预算或拥挤度阻止入场后，预览汇总和子项都报告最终动作及原因。停止后的快照并非实时账户状态；未决订单无法确认时状态为 `unknown` 并要求人工接管，不能沿用旧覆盖量判断安全。`manual_takeover` 为真或未保护数量未知时需人工核对交易所。不要公开提交账户报告。

## 账户状态

固定 `state_dir` 保存 `intents.sqlite`、成交归属、有限观察记录、`latest.json` 和执行锁。同一账户只使用一台机器、一个客户端，Demo 与主网不共用目录。使用独立 BTC/USDT 现货账户；手工订单、已有 BTC、转账和其它资产不会自动认领为程序持仓。账户余额、资金变化或订单归属无法核对时停止新增风险，保留状态并人工核对，不删除数据库或换空目录绕过。当前模型保存已处理开盘时间和已消费信号，重启不会重复换仓或借旧影子信号再入。已有持仓不补仓。残币保留归属并计入持仓和风险，达到数量步长的残币保守阻止新增 BUY。

参数完全相同的单 SMA40 v7 已知规则可以在显式授权的 Demo 会话中升级。程序先校验检查点、持仓、原委托身份、账户余额和属于程序的实际成交；持仓峰值从有证据的 BUY 成交及新报价重建，已确认的原生止损下限继续绑定原持仓；旧的未发送 BUY 作废。全部核对成功后才保存当前规则并继续运行。升级成功后，旧版本会拒绝同一个数据库；切回旧代码不会回退状态，也不会撤去已确认的新保护，不能再让旧版本接管该库。

只读 `status` / `run` 遇到待升级规则仍报告 `blocked`，不能替代执行对账或自动取得 Demo 执行授权。主网旧库只能保留现有原生保护并到交易所人工核对、结清仓位与委托；不要改 `environment`、UID 或数据库把主网状态转成 Demo。主网写权限在新旧版本中都被阻止。

v5、v6、旧三仓、不同参数、未知规则或缺失归属证据的状态拒绝接管。尚未升级的旧库可用写入它的确切旧提交隔离核对：先停止其它程序并备份原状态目录，将下面 `OLD_DEPLOYED_SHA` 替换为该提交，原配置使用绝对路径，且 `state_dir` 仍指向原固定目录；不要创建空库或手工改写旧库。旧版 `status` 也会保存观察记录。

```sh
git worktree add --detach ../spotquant-closeout OLD_DEPLOYED_SHA
cd ../spotquant-closeout
python3 -m spotquant status --config /absolute/path/original-config.json
```

这只恢复旧版本的观察能力，`status` 成功不等于已经平仓。真正的主网收尾需在交易所人工核对并结清 BTC 和剩余委托；结清完成前保留已确认保护。确认无持仓、无未决单后保留原库记录，再处理当前版本的初始化。旧提交不明确或旧库已升级时，不运行旧版本接管，直接保留文件和保护并人工核对。

## 离线检查与排障

```sh
python3 -m compileall -q spotquant tests
python3 -m unittest discover -s tests
```

检查使用离线输入，不连接账户。`blocked` 表示当前权限或配置不允许操作；`unknown` 表示无法确认数据、订单或账户状态，不能当作已成交。先核对 UID、环境、固定状态目录、凭据变量及报告原因；状态不兼容或余额/订单归属不一致时保留原文件，人工核对，不清空重试。
