# 28% 目标与价格带钳制的样本内对照

这是同一固定窗口上的模拟对照，不是原生执行验收。`native_execution_verified` 仍为 false。窗口、会话、成本和分钟路径与已发布的 v0.1.0 回放相同：2020-01-01 00:00 UTC 至 2026-09-20 00:00 UTC（右端不含），初始 10,000 元，795 次会话。结果是样本内的。

策略参数仍是验证高点回撤 28%。Demo 探针已经确认，Binance 对 BTCUSDT 的 `STOP_LOSS` `stopPrice` 使用 `PERCENT_PRICE_BY_SIDE`：均价下方 15% 被接受，20%、25% 和 28% 被拒绝，`code` 为 `-1013`，`msg` 为 `Filter failure: PERCENT_PRICE_BY_SIDE`。当时读到的 `askMultiplierDown` 是 0.8。部署把 `stop_price_percent_band` 设为 true。挂出价取 28% 目标、缓冲后的下限（参考价乘当次乘数再乘 1.001，按 tick 向上取整）和已有止损中的较高者，并且只上移。靠近峰值时，这大约比 5 分钟均价低 20%。代码里该字段的默认值仍是 false：配置省略它时，会话仍发送 28% 目标。乘数每次从该交易对的 `exchangeInfo` 读取，不写死。

## 价格带在回放里怎么建模

已发布回放没有百分比过滤器，均价等于当时的路径价，所以止损就是 28%。选项 A 这次重放把过滤器打开，并把它标成已确认：

- `askMultiplierDown` 用 **0.8**。这和后来 Demo 上 BTCUSDT 读到的现值一致，但回放没有逐年的 `exchangeInfo`，所以 0.8 仍是模型假设，不是实盘代码里的常数。
- `askMultiplierUp` 用 5，卖出止损没有顶到上沿。
- `avgPriceMins` 为 5。参考价是 **已经走完的 5 根 1 分钟 K 线** 的典型价 `(高+低+收)/3`，按基础资产成交量加权。正在走的那一分钟不用，避免用到它尚未发生的高、低、收。这 5 根里如果没有成交量，就改用收盘价的简单平均。
- 实盘里的 0.1% 缓冲和 0.01 tick 向上取整仍由当前的 `clamp_stop` 计算，不在场所里另写一套。

28% 那一列是已发布、并经过独立审计的 fcdb83c 全量回放，这里没有再跑一遍。选项 A 用同一套输入、日程和成本，在当前实现上把开关打开后重跑了全部 795 次会话。`complete` 为 true，没有会话以未解决状态结束，`cycle_error_sessions` 为 0。这次重放的 Python 是 3.12.3；已发布回放是 3.13.16。

胜率按已平仓回合计算：卖出数量用先进先出对应到之前的买入。买入成本是花掉的计价资产，卖出所得是成交额减去 USDT 手续费。所得高于对应成本算赢。期末仍持有的 BTC 不算赢也不算亏。止损次数只数订单类型为 `STOP_LOSS` 的成交，不含后来撤销、没有成交的止损单。
