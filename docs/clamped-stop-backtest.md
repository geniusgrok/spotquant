# 28% 止损与选项 A 的样本内对照

这是同一固定窗口上的模拟对照，不是交易所规则已经被确认，也不是原生执行验收。`native_execution_verified` 仍为 false。窗口、会话、成本和分钟路径与已发布的 v0.1.0 回放相同：2020-01-01 00:00 UTC 至 2026-09-20 00:00 UTC（右端不含），初始 10,000 元，795 次会话。结果是样本内的。

默认实盘行为没有改成钳制。配置 `stop_price_percent_band` 默认为 false，会话仍发送真正的 28% 止损。只有 Demo 探针确认 `STOP_LOSS` 的 `stopPrice` 受该交易对的百分比价格过滤约束之后，才把这个开关设为 true。打开之后，止损取 28% 目标、当次 `exchangeInfo` 给出的卖出下限（再加 0.1% 缓冲并按 tick 向上取整）、以及已有止损中的较高者，并且只上移。乘数不写死。

## 价格带在回放里怎么建模

已发布回放没有百分比过滤器，均价等于当时的路径价，所以止损就是 28%。选项 A 这次重放把过滤器打开，并把它标成已确认：

- `askMultiplierDown` 用 **0.8**。这是文档示例和先前 Demo 拒绝所暗示的数量级，不是从历史 `exchangeInfo` 读到的，也不是实盘代码里的常数。
- `askMultiplierUp` 用 5，卖出止损没有顶到上沿。
- `avgPriceMins` 为 5。参考价是 **已经走完的 5 根 1 分钟 K 线** 的典型价 `(高+低+收)/3`，按基础资产成交量加权。正在走的那一分钟不用，避免用到它尚未发生的高、低、收。这 5 根里如果没有成交量，就改用收盘价的简单平均。
- 实盘里的 0.1% 缓冲和 0.01 tick 向上取整仍由当前的 `clamp_stop` 计算，不在场所里另写一套。

28% 那一列是已发布、并经过独立审计的 fcdb83c 全量回放，这里没有再跑一遍。选项 A 用同一套输入、日程和成本，在当前实现上把开关打开后重跑了全部 795 次会话。`complete` 为 true，没有会话以未解决状态结束，`cycle_error_sessions` 为 0。这次重放的 Python 是 3.12.3；已发布回放是 3.13.16。

胜率按已平仓回合计算：卖出数量用先进先出对应到之前的买入。买入成本是花掉的计价资产，卖出所得是成交额减去 USDT 手续费。所得高于对应成本算赢。期末仍持有的 BTC 不算赢也不算亏。止损次数只数订单类型为 `STOP_LOSS` 的成交，不含后来撤销、没有成交的止损单。

## 对照

| 指标 | 已发布 28% | 选项 A（模型价格带） |
| --- | ---: | ---: |
| 年化 CAGR | 93.42% | 79.23% |
| 最大回撤 | 29.63% | 39.07% |
| 止损成交次数 | 0 | 4 |

显示值四舍五入。原值：28% 的 CAGR 为 0.9341674365727095，最大回撤 0.2962625947106404843238863902，期末权益 841130.9834114773421822619249 元。选项 A 的 CAGR 为 0.7923076943342675，最大回撤 0.3906792707501508024178719664，期末权益 504196.0492191686417975111082 元。

在这个窗口里，把止损抬到模型价格带上方少拿了大约 33.7 万元的期末权益，年化从 93.42% 降到 79.23%，最大回撤从 29.63% 升到 39.07%，并多出 4 笔止损成交。胜率从 16/38 变成 17/39。换来的是：若交易所确实不许挂出 28% 那么深的触发价，持仓不会在下单时就被拒绝。这仍是样本内模拟，不能用来声称实盘会得到同样的曲线，也不能把 `native_execution_verified` 写成 true。
